# 忆织平台：成本估算

[返回首页](../README.md)

估算日期：2026-10-09。以下为设计阶段的预算假设，尚无实际账单。仅计游戏开发调试与演示调用模型的费用，不包含人员、美术、服务器、语音、图片生成或辅助写代码的工具费用。

## 1. 用量模型

普通一局暂估全队 20～30 次调用。用于保守规划的计算口径为：

- 全队合计 30 次调用，包含分析、交流、记忆更新和结案。
- 每次平均 5,000 输入 token、1,000 计费输出 token。
- 一局合计 150,000 输入、30,000 输出 token。
- 不计缓存优惠，不包含额外重试。

计费输出应包含服务商实际计费的思考等输出，不能只统计屏幕显示的文字。若实际超过上述平均值，应重新估算。

费用 = 输入 token / 1,000,000 × 输入单价 + 输出 token / 1,000,000 × 输出单价。

两个比较分支暂按 35～60 次调用估算；相同调查前缀可复用，分叉后的生成另计。录制回放不重新调用模型。

以上口径用于首个合作本的基础原型。阶段性自主整理、方案调整和遗忘前交流会增加调用；对抗角色也可能增加独立决策调用。核心玩法版本与对抗本的费用尚未估算，需按实际事件和调用量重新记录，不能直接沿用本表宣称预算足够。模型计费 token 与游戏中的记忆容量分开统计。

## 3. 开发预算

若主要使用上述 Flash 费率：

| 完整局等量调用 | 基础费用 |
|---|---:|
| 100 局 | ¥27～54 |
| 500 局 | ¥135～270 |
| 1,000 局 | ¥270～540 |

建议基础原型测试先安排 ¥100 额度；基础原型 API 预留 ¥500～1,000，覆盖主要使用经济型模型时的调试、重试和少量其他模型比较。这是预算建议，不是自动充值或支出授权；新增自主整理和对抗角色后需要重新估算。

若全程采用 GPT-6.1 Sol，同口径 500 局约 ¥2,100，不能沿用经济模型预算。

## 4. 实际记录与更新

每次调用记录角色、动作、分支、模型、输入 token、缓存输入、计费输出、耗时、失败/重试与费用。前 20 局结束后，更新每局实际平均费用及较高费用的场景，再决定后续额度。

事件触发模型调用，普通移动动画和卡片状态变化不调用模型。案情会有轮次限制，程序能够直接保存的观察不额外请求模型重写。开发期间控制调用量，但不能为了便宜改变证据或伪造角色行为。
