# 忆织平台：记忆与多智能体机制

[返回首页](../README.md)

本文件约束角色能知道什么、通信如何改变知识，以及导演如何干预外部记忆。它不要求训练新的模型，也不把记忆屏蔽等同于参数层面的遗忘。

平台的核心问题是：某个角色认为可以忘掉的经历，可能仍与队友的信息互补。合作本中的共同目标不消除这一问题；对抗本则允许部分角色利用隐瞒或误导影响记忆取舍。当前只有设计，尚未实现自动遗忘机制。

## 1. 状态分层

| 状态 | 内容 | 哪些角色可读 |
|---|---|---|
| 世界状态 | 案件真相、固定时间线、动作与原始证据 | 环境和结案检查器；侦探仅通过合法动作取得相应材料 |
| 私人记忆 | 该侦探获取的观察、收到的转述、形成的推断 | 该侦探 |
| 收件消息 | 实际发送给该侦探的消息和附件 | 接收者 |
| 公共证据板 | 明确共享给全队的材料 | 全队 |
| 观察者日志 | 完整事件、各成员输入输出、导演操作、用量 | 调试/导演界面；不自动输入角色 |

同一模型配合独立输入和状态即可实现三名角色。不得把完整世界真相或全部私人记忆作为“背景说明”一起发送。

## 2. 记忆条目

首版每条记忆包含所属角色、正文、类型、来源、获取时间、事件时间、依据编号及状态。

类型为观察、转述或推断。状态可以是可用、被质疑、已被更正或导演屏蔽。每条记录有普通唯一 ID 用于引用；无需内容哈希或指纹。

例如，“林舟声称得到授权”应是带说话人来源的转述；“因此搬运合法”则是另一条可能被推翻的推断。两者不能合成一条没有来源的事实。

基础原型材料数量有限，可直接从当前角色的可用记录构造输入，暂不引入自动摘要。核心玩法版本再接入阶段性整理；向量数据库与跨剧本检索不属于当前实现要求。

上述是基础原型的存储方式；核心玩法版本需要加入下文的阶段性整理。世界中的原始记录可以仍然存在，但不能免费回注角色，重新取得必须经过剧本中的合法动作。

## 3. 一次模型调用

输入只包含：角色职责、公共任务、当前分支的可用私人记忆、已收到的消息及本次动作观察。公共材料只包括真实共享的部分。

输出包含短汇报、引用的已有证据、待核实问题和建议的合法动作。模型可以提出假设，但不能通过输出直接创建原始证据、修改真相或执行未获批准的调查。

环境执行与角色解读分开：程序先保存原始观察，再调用模型解读。首次调查后可在两者之间保存导演检查点，避免干预前已经产生同内容的摘要或判断。

## 4. 通信

一次通信显式记录发送者、接收者、正文和附件。接收者可以读取实际发送的正文与附件，不能仅凭其中一个编号访问后台所有证据。

没有附件的转述仍然有用，但它是来源为队友的说法。后续需要查验时，可以向持有者请求分享原始材料。私人材料进入公共板必须有明确的全队分享事件。

已共享材料可以作为团队的冗余记忆：发送者本地忘记之后，接收者仍可能提供它。不会为了制造失忆效果强制抹除队友副本。

## 5. 更正

新证据反驳旧判断时，保留旧记录并标明其状态，新增更正依据。更正先影响获得新证据的成员；其他成员要通过消息收到它，不能自动同步全部私人状态。

模型提出更正时需引用它实际持有的材料。事实观察不因模型一句否定就从世界中消失。原始记录、关于记录的判断、记录后来被更正的事件需要区分。

## 6. 记忆屏蔽与恢复

首版支持在首次材料获取完成、成员尚未分析和对外汇报的节点屏蔽指定卡片。屏蔽只是当前分支、当前角色的外部记忆读取状态变化。

每次推理重新按当前分支构造输入，不续接一个仍包含屏蔽正文的隐藏模型会话。完整日志可以供导演查看，但不回注角色。卡片在导演界面中呈灰色，不代表角色仍能看到其正文。

恢复有两种路径：导演重新启用卡片；或角色通过合法通信/调查重新获得同一信息。重新调取原始凭条消耗调查行动点，不能通过隐藏的免费日志读取实现。

首版不声称支持任意时刻的全团队语义删除。已经分享、推断或总结之后，单独屏蔽一张原始卡片不能保证所有语义副本消失。如果以后加入此功能，需要单独定义干预范围和衍生记录处理规则。

## 7. 分支和回放

只在一个事件完整结束后保存快照，不在流式生成中途截断。快照保存世界进度、各角色记忆和收件消息、公共板、行动点、待执行任务及模型配置。

两个分支从同一快照启动，后续状态互不修改。导演操作记录在对应分支事件中。原始案件事实在分支间保持一致。

录制回放展示已保存的真实事件，不重新请求模型。实时分支会产生新输出，即使配置相同也不保证逐字重复。比较时展示实际结果，不把单次差异直接归因为记忆机制的普遍效果。

## 8. 运行边界

案情会最多两轮；每局设置明确的模型调用上限。失败调用显示失败并允许重试，重试单独计量，不用预写台词伪装成功。

角色输出引用不存在或未获取的证据时，不允许这些编号进入正式证据链。界面保留必要的失败信息供调试，不自动从全知后台补齐模型缺失的内容。

## 9. 必要验证

| 检查 | 能发现什么问题 | 失败后动作 |
|---|---|---|
| 检查角色实际输入 | 世界答案或其他人的私人材料泄漏 | 修正输入构造，再继续测角色行为 |
| 屏蔽前后检查输入 | 被屏蔽内容仍从聊天、摘要或日志进入 | 修正状态投影与检查点，不能仅改卡片颜色 |
| 对照消息与附件 | 只传编号却授予原文访问 | 修正消息接收和附件读取 |
| 恢复快照后运行独立分支 | 两个分支共享可变状态 | 修正快照与分支状态管理 |
| 观察旧消息接收者 | 更正无通信就自动同步 | 修正接收者更新路径 |

这些验证与实现阶段配套执行。当前没有可运行实现，也没有已通过的检查结果。

## 10. 阶段性整理与团队记忆

整理在剧本定义的阶段边界触发。每个角色仅根据自己的可见材料提出保留、压缩、遗忘方案和理由；队长可保护已汇报片段、要求交流或批准公开。伙伴收到需要的信息后，可以说明某段经历仍对自己有用，角色再根据新消息调整方案。

队长不能通过批准按钮获得原本不可见的正文。保护条目仍计入容量，公共板也有容量约束；超额方案先调整，不能悄悄截断或免计。实际读取文本及进入输入的来源元数据按 token 计量，卡片数量仅作界面呈现；容量与保护额度待试玩确定。共享副本和角色实际保留的转述各自占相应空间，不默认免费去重。

压缩摘要应记录来源和实际保留的内容。引用原始证据编号并不等于保留其全部事实；归档原文、世界材料、观察者日志不能仅凭编号免费读取。结案必须使用当前可用且已合法共享的支持内容，不能因后台曾取得原件就自动补足摘要遗漏的字段。基础原型仍使用完整证据卡；摘要参与结案前需要明确事实字段与支持关系的表示方式。

整理提交前后记录实际记忆状态，用于结局复盘。展示哪些事实保留或丢失，基于实际内容和剧本明确的事实字段，不编造模型的内部思考。未知的后续用途不能由全知后台代替角色预测。

## 11. 合作、对抗与可见范围

合作队员共同追求胜利，可以判断错误、忘掉细节或求助，但不能被设定为暗中追求破坏目标。对抗角色的隐藏目标和行动权限由剧本配置，必须仅基于自身知识行动。

对抗角色可以隐瞒自己的信息、发送误导性陈述、建议不当整理或按规则遗忘自身记录。误导消息仍标明发送者和实际附件，不能伪造为真实设备观察。它不能直接改写别人的状态、原始记录、公共板或已发送副本；如未来剧本允许修改公共材料，必须单独定义合法动作及可观察痕迹。

玩家只读取其获得的汇报、消息与公共材料，不显示隐藏目标或未公开私人正文。完整记忆、隐藏目标与事件日志在结局复盘或独立导演工具中查看；导演干预分支标注为调试/演示。普通游玩不能免费调用导演恢复功能。

## 12. 恢复、终止与验证

关键支持信息的首次获取、重新获取和替代路径由剧本预先定义，注明所需线索、来源与行动代价。重新调查产生新的获取事件；队友提醒从其实际可用记忆产生消息。原持有者遗忘不消除队友副本，恢复也不临时生成新事实。

资源允许时，玩家可以补查；资源耗尽且证据不足时，进入未完成结局与复盘。服务故障或调用上限属于技术暂停，不能伪装成角色遗忘或故事失败。规则允许失败，但必须有明确的后续行动或终止入口。

实现核心玩法时增加以下有针对性的检查：

| 检查 | 具体失败 | 失败后动作 |
|---|---|---|
| 整理前后实际输入与计量 | 已遗忘事实仍经摘要/副本输入，或保护/公共板超额免计 | 修正状态提交和容量计量，再继续游玩 |
| 摘要与结案支持内容 | 仅凭编号或后台原件自动补齐未保留事实 | 明确事实表示与当前可用支持检查 |
| 恢复动作及资源耗尽路线 | 免费读取日志、临时创造救场线索或无终止入口 | 修正剧本动作与结束规则 |
| 对抗角色动作与玩家视图 | 越权删除他人记忆、改写真相或直接泄露秘密 | 修正合法动作边界和视图数据 |
