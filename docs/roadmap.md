# 忆织平台：开发路线

[返回首页](../README.md)

当前仅完成设计文档。以下阶段均待开发；技术框架、模型和具体工期尚未锁定。

开发顺序：合作本基础原型 → 团队记忆取舍的核心玩法版本 → 展示打磨 → 对抗本与其他题材。正式名称为“忆织平台 / MnemoWeave”，仓库名为 `mnemoweave`。

## 阶段一：把固定案件做成可玩的流程

目标：不依赖模型也能检查案件规则、行动预算和界面状态是否正确。

- [ ] 将[首案配置](cases/moonstone.md)中的人物、地点、动作、证据与支持关系转成结构化数据。
- [ ] 实现地图、任务按钮、角色状态、证据卡和行动点。
- [ ] 实现原始证据获得、指定分享和公共证据板。
- [ ] 实现人物、位置、授权状态及其证据的分项结案检查。
- [ ] 用明确标注的开发测试数据跑通正常路线与错误路线。
- [ ] 实现重新获取、替代取证，以及行动耗尽后的未完成结局与复盘入口。

完成条件：基础原型正常路线在 8 点内可结案；只有猜测、只有去向或未经核实的说法不会被判为完整解决。屏蔽 E03 后有预先定义的补查路线；耗尽行动点可以结束并复盘，不卡在没有操作的界面。开发测试数据不作为实时 AI 演示素材。

## 阶段二：接入三名独立记忆的 AI

- [ ] 实现每位角色的私人记忆和收件消息。
- [ ] 按角色构造模型输入，隔离后台真相和其他人的私人材料。
- [ ] 生成短汇报、待核实问题、依据及合法动作建议。
- [ ] 实现消息正文、附件、全队共享及有限案情会。
- [ ] 玩家批准调查后，由环境执行固定动作并返回材料。
- [ ] 记录每次调用的 token、模型、耗时和费用。
- [ ] 将三名队员配置为共同追求解决案件，不混入隐藏破坏目标。

完成条件：从实际请求可确认信息边界；获得材料、分享材料和随后使用材料之间有真实对应关系。模型报错会明确显示，不能伪造输出。

## 阶段三：做出记忆干预与分支比较

- [ ] 在初查材料入库、角色分析前建立快照。
- [ ] 支持屏蔽或恢复 E03。
- [ ] 从同一快照建立独立分支，继承相同行动点。
- [ ] 允许通过重新调查或替代证据链补回支持。
- [ ] 对比新增调查动作、共享材料、最终结论、引用依据和费用。

完成条件：屏蔽内容不再进入该分支的角色请求；基线分支不受影响；合法恢复后角色能重新使用材料；如果两个分支表现相同，也如实展示。

## 阶段四：让记忆取舍成为实际玩法

- [ ] 在剧本阶段边界定义整理节点，不要求每次对话都手动管理。
- [ ] 根据角色实际可见信息，生成保留、压缩、遗忘方案和理由。
- [ ] 实现保护已汇报片段、整理前交流、有限公共板与方案调整。
- [ ] 用实际读取文本的 token 计量容量，计入保护条目、公共板与输入中的来源元数据；试玩确定额度和交流代价。
- [ ] 明确摘要保留的事实字段及其支持关系，避免原件编号自动赋予完整内容。
- [ ] 实现整理前后状态记录，以及结局的信息流转复盘。
- [ ] 检查遗忘后角色实际输入、合法恢复、行动耗尽与结束入口。
- [ ] 重新试玩行动节奏与调用量，不沿用基础原型的 8 点和费用估算保证。

完成条件：记忆容量真实影响后续可读信息；角色方案只依据自身知识；玩家的保护、交流和补查会改变实际状态；结局支持来自当前合法可用内容。允许两个安排结果相同或协作安排失败，不预写必然胜负。

这一步承接“局部看来可以忘、团队组合仍可能需要”的研究问题，但尚无新算法或效果结论。手动屏蔽只是前一阶段的验证工具，不能冒充自主压缩。

## 阶段五：完善可展示性

- [ ] 获取、分享、更正三个事件有清晰的卡片反馈。
- [ ] 支持预设匿名传闻，保留来源类型。
- [ ] 展示授权说法被新记录反驳后的更正与传播。
- [ ] 支持真实事件的录制回放，清楚区分实时与回放。
- [ ] 打磨一次 3～5 分钟讲解流程，实测响应时间后调整节奏。
- [ ] 汇总前 20 局用量，更新[预算](cost-estimate.md)。

完成条件：观众无需阅读长聊天，也能看懂谁知道什么、遗忘前怎样交流、缺失如何补回以及结论缺少什么依据。普通游玩、完整复盘、导演干预和录制回放标识清楚。

## 阶段六：扩展剧本与对抗角色

- [ ] 增加另一个题材的手写剧本，复用信息获取、通信、整理、恢复与结局规则。
- [ ] 为对抗角色定义隐藏目标、初始知识、合法行动及胜负条件。
- [ ] 支持选择性汇报、带来源的误导转述与整理建议；不得直接改写他人记忆或世界真相。
- [ ] 普通玩家视图不暴露未公开记忆和目标，结束后允许揭晓完整轨迹。
- [ ] 开启导演完整视图后，将分支标记为调试/演示，不混为正常对抗局。
- [ ] 验证误导可被剧本中已有的调查路径查验，动作耗尽有明确结局。

完成条件：对抗行为有目标、有知识依据且遵守世界规则；隐瞒可以影响团队，玩家也有规则内的核查机会。首案中的预写嫌疑人说法不计为已完成此阶段。

## 建议的实现分工

| 工作 | 交付物 |
|---|---|
| 案件与规则 | 案件数据、动作返回、支持关系、结案逻辑 |
| 智能体与记忆 | 输入构造、通信、记忆状态、模型调用 |
| 界面与演示 | 地图、卡片、时间线、导演操作和对比页 |

一人开发时按阶段推进；多人开发时可以按以上边界拆分，但先约定事件和状态字段。此表不预设参与人数或授权额外代理执行。

## 技术取舍

- 采用一个网页前端和轻量后端，框架按学生熟悉程度选定。
- 案件较小，先用普通结构化存储；无需向量数据库。
- 直接保存原始观察；需要解读、表达或协作时才调用模型。
- 三名角色可用同一模型，先保证状态隔离和真实通信。
- 不提前创建空的训练、评测平台或多案件生成框架。

## 首版暂不包含

自主对抗角色、其他题材、自动生成剧本、任意时刻的全团队语义删除、记忆交换、开放世界、三维场景、语音、多人联网、模型训练与跨剧本经验。

基础原型先验证规则与信息边界，核心玩法版本再接入容量约束与自主整理。对抗本在合作本可玩后扩展；具体压缩方法以后可替换和比较，不预建训练平台，也不宣称尚未验证的方法已经优于现有方案。
