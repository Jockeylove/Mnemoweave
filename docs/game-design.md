# 忆织平台：游戏设计

[返回首页](../README.md)

状态：设计阶段，尚未实现或实测。平台支持不同题材的剧本，先完成一个合作本；[首案配置](cases/moonstone.md)保存《月光石》的固定真相。本文中的队长、调查和结案是首案用语，其他剧本可以对应任务分配、探索和任务结局。

## 1. 玩家与目标

玩家担任侦探队长，通过任务分配、成员交流和定向核查完成案件。结案需要回答人物、物品位置与授权状态三个问题，并给出已获得的证据。

只有主角由人类玩家控制，三名队员是拥有独立状态和记忆的 AI NPC。玩家除了决定去哪调查，还要安排谁记住什么、什么时候互相提醒，使团队在有限记忆下继续合作。“合作本”不要求多名人类玩家。

第一版采用按钮、卡片和少量可选短文本输入。调查动作由明确选项触发；自由文本用于询问和说明，不直接修改世界状态。

## 2. 剧本类型与查看方式

剧本类型决定角色目标，与游玩/导演视图分开。

| 剧本类型 | 角色目标 | 主要挑战 | 开发顺序 |
|---|---|---|---|
| 合作本 | 队员共同追求任务胜利 | 分散信息、有限记忆、误解、遗忘与补查 | 首案与第一版 |
| 对抗本 | 部分角色表面合作，实际追求隐藏目标 | 判断遗忘还是隐瞒，查验误导信息，维持团队协作 | 合作本可玩后再扩展 |

合作队员不能故意破坏共同目标，但不保证判断正确或记忆选择正确。对抗角色必须有明确的动机、可知信息和合法行动，不采用随机捣乱。它可以选择性汇报、提出误导性整理建议、编造带来源的转述，或遗忘自己的记录；不能直接删除别人记忆、修改后台真相或读取未知材料。建议也必须经过正常通信与队长决策，不能暗中触发他人的删除。

对抗本中玩家需要从已知材料判断队友是否隐瞒。全部私人记忆和隐藏目标不得在普通游玩中直接揭示。

| 模式 | 身份 | 可见内容 | 可操作内容 |
|---|---|---|---|
| 破案模式 | 队长 | 已汇报的材料、公共证据板、任务状态 | 分配调查、指定交流、组织案情会、批准追查、提交结论 |
| 结局复盘 | 玩家 | 已结束剧本的完整信息流转、记忆变化与目标揭晓 | 查看经历、来源、整理和实际使用的对应关系 |
| 导演工具 | 调试/演示观察者 | 三名成员的完整外部记忆、事件记录、分支状态 | 暂停、建立分支、屏蔽/恢复记忆、加入预设传闻、查看对比 |

导演工具独立于正常游玩；开启完整信息视图的分支标记为演示/调试，不能继续当作未知秘密的普通对抗局。查看完整记录不向角色传递新事实。若观察者主动将材料转告队友，系统应记录来自队长的通信。正式游玩过程中不能免费切入导演工具恢复记忆。

## 3. 角色

| 角色 | 职责与能力 | 表达特点 |
|---|---|---|
| 阿镜 | 勘查、查看录像、搜索地点 | 描述具体观察，少作无依据的联想 |
| 闻声 | 访谈、追问、查看人物提供的凭据 | 区分当事人的说法和可核查记录 |
| 书衡 | 核对登记、器材领用、申请有效状态 | 重视编号、时间和记录版本 |

三名队员以解决案件为共同目标；个性影响表达，不改变案件事实或原始证据。三名嫌疑人是案件中的固定 NPC，第一版不为他们分别部署自主智能体。林舟的未核实授权说法是预写的案件陈述，不代表首案已经实现自主对抗角色。

## 4. 基本循环

1. 队长选择角色和一项合法调查任务。
2. 环境按固定案件配置返回材料或“未发现相关信息”。
3. 材料进入该角色的记忆本。
4. 角色读取自己可用的信息，给出短汇报、待核实问题和下一步建议。
5. 队长决定继续调查、指定分享，或召开案情会。
6. 证据足够时，由队长提交结案。

首次调查完成后，在步骤 3 与步骤 4 之间提供一个明确检查点：材料已经取得，但成员尚未分析、总结或对外分享。首版的记忆屏蔽演示从这里分支。

### 核心玩法版本的记忆整理节点

基础原型先用屏蔽验证状态变化与恢复路径。随后加入阶段性的整理节点，而非每次对话都要求玩家手动管理卡片：

1. 分头经历后，角色根据自己的可见材料提出保留、压缩或遗忘方案，并说明理由。
2. 队长查看角色汇报的方案，可以保护片段、要求先交流，或存入公共证据板。未汇报的私人正文不会因整理界面自动公开。
3. 角色在获得新消息后重新提出方案，程序按容量与批准规则提交新记忆状态。
4. 团队继续行动；缺失信息可由队友提醒、重新调查或替代路线补回。
5. 结局回看信息变化与实际使用；不预设独立整理必然失败或协作整理必然成功。

容量约束同时覆盖实际读取的私人记忆和公共板，保护条目也占容量，不能把公共板当无限存储。容量和保护额度尚未定值，需要试玩。展示用卡片不是严谨的容量单位；实现时按实际读取文本的 token 计量，进入输入的来源和元数据同样计入。各次交流和补查的行动代价由剧本统一定义，不能在遗忘后临时调整。

## 5. 行动与节奏

暂定每局 8 个行动点。该数值是待试玩调整的游戏参数。

| 行为 | 消耗 | 说明 |
|---|---:|---|
| 一项调查任务 | 1 点 | 初查、查询记录、搜索地点、重新调取凭条均属于调查 |
| 一次案情会 | 1 点 | 最多两轮，每轮三人各一次模型调用 |
| 分享已有证据 | 0 点 | 仍消耗模型调用额度；不能借此免费获取新世界材料 |
| 提交结论 | 1 点 | 达到最后一点时仍允许提交 |
| 导演操作 | 0 点 | 不发生在故事世界中；各分支继承相同剩余行动点 |

参考路线：三人初查（3）→ 案情会（1）→ 核对申请（1）→ 搜索温室（1）→ 结案（1），共 7 点。

额外的一点可用于恢复缺失证据或查询替代证据。当前 8 点与免费分享适用于基础原型；加入容量约束后，需要重新试玩节奏和交流代价，不能据此保证任意压缩后的路线都可在 8 点内完成。自由分享仍受每局模型调用上限约束，不让角色无限对话。

故事中的行动点耗尽且无法完整提交时，进入“调查未完成”的结局与复盘，不能停留在无事可做的界面。技术上的模型调用上限或服务失败则明确暂停并显示原因，不能冒充故事结局或静默补充预算。

## 6. 交流与玩家选择

队长可以选择把某人的发现发给某位伙伴，或发给全队。发送者基于自己的知识生成短消息，并附上实际选中的证据卡；接收者只获得这次消息和附件。

案情会第一轮通报发现，第二轮回应冲突和提出追查建议。队长可以采纳某个建议，也可以另选合法调查动作。公共证据板只展示实际共享给全队的材料。

第一版不自动把所有私人记忆拼成一个大提示词。玩家能否及时安排信息交流，是玩法的一部分。

互补信息是记忆取舍的重点：阿镜知道 K17 在 20:10 开柜，闻声知道林舟借用 K17 的时间。借用细节对闻声当前访谈可能不显眼，却对团队关联人物和事件有用。整理方案应体现角色实际知道的内容；不得从后台答案替它判断哪些细节必须保留。

## 7. 界面布局

```text
┌─────────────────────────────────────────────────────┐
│ 忆织 / MnemoWeave        剩余行动：5   实时 / 回放  │
├─────────────┬───────────────────┬───────────────────┤
│ 侦探队      │ 山庄二维地图      │ 公共证据板        │
│ 阿镜        │ 五个可调查地点    │ 已共享线索        │
│ 闻声        │ 当前调查事件      │ 有依据的判断      │
│ 书衡        │                   │ 待核实问题        │
├─────────────┴───────────────────┴───────────────────┤
│ 事件时间线：发现 → 分享 → 质疑 → 更正 → 追查         │
├─────────────────────────────────────────────────────┤
│ 调查任务  指定交流  案情会  结案   [导演模式]        │
└─────────────────────────────────────────────────────┘
```

点击头像展开记忆抽屉。破案模式只展示已汇报的部分和实际收到的整理方案；导演工具可查看全部外部记忆，对抗本游玩时不能显示未公开目标。证据卡区分观察、转述、推断，并标明来源和状态。核心玩法版本增加阶段性整理面板，结局增加信息流转复盘。

动画与真实事件绑定：新卡进入记忆本、附件发送给队友、旧说法被标为已更正。点击结论可以高亮实际引用的卡片，不展示没有定义或没有测量的“智商”“记忆健康度”。

## 8. 结案体验

玩家提交人物、地点、授权判断及相应依据。界面逐项展示：

- 答案和证据完整：案件解决。
- 人物方向正确但缺少支持：证据尚不完整。
- 只有物品去向线索：需要进一步搜索确认。
- 证据与结论不符：指出不支持的字段，剩余行动点允许时可继续调查。

具体答案和等价证据组合由案件配置定义。不同字段分别检查，不要求模型输出固定句式。

关键事实应有预先定义的获取、恢复或替代证据途径，并标明前提和代价。恢复动作重新访问世界中的来源，不免费读取观察者日志。已经传给队友的副本不会随原持有者遗忘自动消失。

规则保证有明确的可行动路径和终止状态，不保证每局获胜。玩家用尽机会、没有查验说法或让重要信息失去可用来源，都可以导致合法失败；剧本不能临时生成新线索、自动补回被遗忘内容或强行修正模型判断。

## 9. 首版边界

基础原型包含一个固定合作案件、三个独立记忆的 AI、二维界面、指定检查点的记忆干预、合法恢复、分支对比与明确标注的回放。核心玩法版本进一步加入阶段性记忆容量、角色整理方案、遗忘前交流与保护以及结局复盘；这些均尚未实现。

对抗本、其他题材、开放世界、动态生成案件、自由语音、多人联网、三维场景、跨剧本经验和模型训练不属于首案交付要求。先做可玩的合作本，再扩展；不将手动屏蔽当成自动压缩或新遗忘算法。
